TypeScript, as a superset of JavaScript, enhances JavaScript’s dynamic typing by introducing static types, enabling developers to define the shape of data explicitly. This ensures type safety, reduces runtime errors, and improves code maintainability. Below is a comprehensive guide to data types in TypeScript, covering primitive types, complex types, special types, type annotations, and advanced features.

---

### **1. Primitive Types**

Primitive types are the basic building blocks for data in TypeScript.

#### **a. `number`**

- Represents both integers and floating-point numbers.
- Example:
  ```typescript
  let age: number = 25;
  let price: number = 99.99;
  // age = "twenty"; // Error: Type 'string' is not assignable to type 'number'
  ```

#### **b. `string`**

- Represents textual data (single quotes, double quotes, or template literals).
- Example:
  ```typescript
  let name: string = "Alice";
  let greeting: string = `Hello, ${name}!`; // Template literal
  ```

#### **c. `boolean`**

- Represents `true` or `false` values.
- Example:
  ```typescript
  let isActive: boolean = true;
  let hasAccess: boolean = false;
  ```

#### **d. `null`**

- Represents the intentional absence of a value.
- Example:
  ```typescript
  let empty: null = null;
  ```

#### **e. `undefined`**

- Represents a variable that has been declared but not assigned a value.
- Example:
  ```typescript
  let notAssigned: undefined = undefined;
  let x: number | undefined; // Variable declared but not initialized
  ```

#### **f. `symbol`**

- Represents unique, immutable identifiers, often used as object keys.
- Example:
  ```typescript
  let sym: symbol = Symbol("unique");
  ```

#### **g. `bigint`**

- Represents whole numbers larger than `2^53 - 1` (JavaScript’s `Number` limit).
- Example:
  ```typescript
  let bigNum: bigint = 12345678901234567890n;
  ```

### **2. Complex Types**

Complex types are used to represent more structured or composite data.

#### **a. `array`**

- Represents a collection of elements of the same type.
- Two syntaxes:
  - `Type[]`: `let numbers: number[] = [1, 2, 3];`
  - `Array<Type>`: `let names: Array<string> = ["Alice", "Bob"];`
- Example:
  ```typescript
  let scores: number[] = [90, 85, 88];
  // scores.push("80"); // Error: Argument of type 'string' is not assignable to parameter of type 'number'
  ```

#### **b. `object`**

- Represents non-primitive types (e.g., objects, but not specific structures unless defined).
- Usually, specific object shapes are defined using interfaces or type aliases (see below).
- Example:
  ```typescript
  let obj: object = { name: "Alice" };
  // obj = 42; // Error: Type 'number' is not assignable to type 'object'
  ```

#### **c. `tuple`**

- Represents an array with a fixed number of elements of specific types.
- Example:
  ```typescript
  let person: [string, number] = ["Alice", 25];
  // person[0] = 30; // Error: Type 'number' is not assignable to type 'string'
  ```

#### **d. `enum`**

- Represents a set of named constants, useful for defining a fixed set of values.
- Example:
  ```typescript
  enum Status {
    Active, // 0 (default, unless specified)
    Inactive, // 1
    Pending = 10, // Custom value
  }
  let userStatus: Status = Status.Active; // 0
  ```

#### **e. `function`**

- Functions can have typed parameters and return types.
- Example:
  ```typescript
  let add: (a: number, b: number) => number = (a, b) => a + b;
  // let result: string = add(2, 3); // Error: Type 'number' is not assignable to type 'string'
  ```

### **3. Special Types**

TypeScript provides special types for flexibility and safety.

#### **a. `any`**

- Disables type checking, allowing any value. Use sparingly as it defeats TypeScript’s purpose.
- Example:
  ```typescript
  let anything: any = 42;
  anything = "Hello"; // No error
  anything = true; // No error
  ```

#### **b. `unknown`**

- A safer alternative to `any`. Represents any value but requires type checking or assertion before use.
- Example:
  ```typescript
  let value: unknown = 42;
  // let num: number = value; // Error: Type 'unknown' is not assignable to type 'number'
  if (typeof value === "number") {
    let num: number = value; // OK after type check
  }
  ```

#### **c. `void`**

- Used for functions that return no value.
- Example:
  ```typescript
  function logMessage(): void {
    console.log("Hello!");
  }
  ```

#### **d. `never`**

- Represents values that never occur, such as functions that always throw or never return.
- Example:
  ```typescript
  function throwError(message: string): never {
    throw new Error(message);
  }
  ```

#### **e. `union`**

- Allows a variable to hold multiple types using the `|` operator.
- Example:
  ```typescript
  let id: number | string = 123;
  id = "ABC123"; // Valid
  // id = true; // Error: Type 'boolean' is not assignable to type 'number | string'
  ```

#### **f. `intersection`**

- Combines multiple types into one using the `&` operator.
- Example:
  ```typescript
  type A = { name: string };
  type B = { age: number };
  let person: A & B = { name: "Alice", age: 25 };
  ```

---

### **4. Type Aliases and Interfaces**

Both are used to define custom types, especially for objects.

#### **a. Type Aliases**

- Defined using the `type` keyword, versatile for any type (including primitives, unions, etc.).
- Example:
  ```typescript
  type Point = { x: number; y: number };
  let point: Point = { x: 10, y: 20 };
  ```

#### **b. Interfaces**

- Defined using the `interface` keyword, primarily for object shapes. Supports declaration merging.
- Example:
  ```typescript
  interface User {
    name: string;
    age: number;
  }
  let user: User = { name: "Bob", age: 30 };
  ```

#### **c. Differences**

- **Type Aliases**: More flexible (can represent primitives, unions, etc.).
- **Interfaces**: Better for objects and support extending/merging.
- Example of Interface Extension:
  ```typescript
  interface Person {
    name: string;
  }
  interface Employee extends Person {
    id: number;
  }
  let employee: Employee = { name: "Alice", id: 101 };
  ```

### **5. Type Inference**

TypeScript automatically infers types when variables are initialized without explicit annotations.

- Example:

  ```typescript
  let num = 42; // Inferred as number
  let str = "Hello"; // Inferred as string
  // num = "Test"; // Error: Type 'string' is not assignable to type 'number'
  ```

- Use explicit annotations when inference might be unclear (e.g., function parameters or complex objects).

### **6. Advanced Type Features**

#### **a. Literal Types**

- Restrict a variable to specific values.
- Example:
  ```typescript
  let direction: "left" | "right" = "left";
  // direction = "up"; // Error: Type '"up"' is not assignable to type '"left" | "right"'
  ```

#### **b. Type Guards**

- Narrow types within a block using checks like `typeof`, `instanceof`, or custom predicates.
- Example:
  ```typescript
  function processValue(value: number | string) {
    if (typeof value === "number") {
      return value * 2; // value is number here
    }
    return value.toUpperCase(); // value is string here
  }
  ```

#### **c. Type Assertions**

- Tell TypeScript to treat a value as a specific type using `as` or angle-bracket syntax.
- Example:
  ```typescript
  let value: unknown = "Hello";
  let str: string = value as string; // Assertion
  let str2: string = <string>value; // Alternative syntax
  ```

#### **d. Generics**

- Allow reusable types with placeholders for flexibility.
- Example:
  ```typescript
  function identity<T>(value: T): T {
    return value;
  }
  let num: number = identity<number>(42); // T is number
  let str: string = identity<string>("Hello"); // T is string
  ```

#### **e. Mapped Types**

- Create new types by transforming existing ones.
- Example:
  ```typescript
  type ReadOnly<T> = { readonly [K in keyof T]: T[K] };
  interface User {
    name: string;
    age: number;
  }
  let user: ReadOnly<User> = { name: "Alice", age: 25 };
  // user.name = "Bob"; // Error: Cannot assign to 'name' because it is a read-only property
  ```

#### **f. Conditional Types**

- Define types based on conditions.
- Example:
  ```typescript
  type IsString<T> = T extends string ? "yes" : "no";
  type Test1 = IsString<string>; // "yes"
  type Test2 = IsString<number>; // "no"
  ```

### **7. Best Practices**

- **Use Specific Types**: Avoid `any` and prefer `unknown` or specific types for safety.
- **Leverage Type Inference**: Omit annotations when TypeScript can infer correctly.
- **Use Union Types Sparingly**: Narrow types with type guards to avoid complex checks.
- **Define Reusable Types**: Use `type` or `interface` for complex object shapes.
- **Enable Strict Mode**: In `tsconfig.json`, set `strict: true` to catch type errors early.
- **Validate External Data**: Use type assertions or guards for API responses or user input.
  ```typescript
  // Example with xAI API (hypothetical)
  interface GrokResponse {
    message: string;
    success: boolean;
  }
  async function fetchGrokData(): Promise<GrokResponse> {
    const response = await fetch("https://x.ai/api"); // See https://x.ai/api for details
    const data: unknown = await response.json();
    if (
      data &&
      typeof data === "object" &&
      "message" in data &&
      "success" in data
    ) {
      return data as GrokResponse;
    }
    throw new Error("Invalid API response");
  }
  ```

---

### **8. Common Pitfalls**

- **Overusing `any`**: Leads to loss of type safety.
- **Incorrect Type Assumptions**: Always validate dynamic data (e.g., API responses).
- **Complex Union Types**: Can make code hard to maintain; consider type guards or restructuring.
- **Ignoring `strictNullChecks`**: Enable in `tsconfig.json` to avoid `null`/`undefined` errors.

---

### **9. Integration with Tools**

- **tsconfig.json**: Configure type checking (e.g., `strict`, `noImplicitAny`).
- **IDE Support**: Use VS Code or WebStorm for type hints and error detection.
- **Linting**: Combine with ESLint for type-aware linting.
- **Testing**: Use typed test frameworks like Jest with `ts-jest`.
